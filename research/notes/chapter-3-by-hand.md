# Chapter 3 — by hand

What the Chapter 3 sessions could not check without a click, a device or an account, in phase order, with the launch command for each step. Sessions append to it; the user works through it at the end of the chapter (3.9 also has the Chapter 2 list once more on RoomCore). Friction goes into `docs/backlog.md` with the phase as the source.

## Setup

1. Build the fork and both RoomCore apps: `bash -c 'ROOM_BUILD_JOBS=6 nohup scripts/roomcore-build.sh > build/roomcore-build.log 2>&1 &'`, then `scripts/roomcore-package.sh` (Room.app on RoomCore in `build/roomcore/DerivedData`, the embryo host in `build/roomcore-host/DerivedData`).
2. The CEF app for comparison: `xcodegen && xcodebuild -scheme Room -configuration Debug -derivedDataPath build/DerivedData build`.

## Phase 3.1a

1. **The laptop's checkout drops patch 0010.** Its `room` branch carries PR #1's twelve patch commits, 0010 included; `scripts/roomcore-apply.sh` only adds missing patches, so it reports "0 applied, 11 already" while 0010 stays compiled in. In `$CHROMIUM_SRC` on the laptop: `git checkout room`, find the 0010 commit with `git log --oneline tags/154.0.8037.58..room` (subject `room: 0010-shutdown-worker-start-priority`), drop it with `git rebase --onto <0010>^ <0010> room`, then `scripts/roomcore-apply.sh` (expect "patches: 0 applied, 11 already on the room branch") and `scripts/roomcore-build.sh`. Needed before 3.1b's release build on the laptop.
2. **Room.app on RoomCore, by hand** (light, then dark):
   `build/roomcore/DerivedData/Build/Products/Debug/Room.app/Contents/MacOS/Room -RoomStateDirectory /tmp/room-3.1a -RoomEngineDirectory /tmp/room-3.1a/engine -RoomSidebarFixture demo`
   Click through the sidebar entries (each page loads in the card), type a URL in the header field and with ⌘T, scroll and click links in a page, go back and forward with the menu, ⌘W a Today tab, ⌘Q. Expected gaps until their phases: no favicons, padlock or theme colour (3.3a), no find, zoom, print, DevTools (3.3b), no popups or `target=_blank` (3.2a), keys typed into the page do not fall through to Room's menu (⌘T/⌘L from inside a page: 3.2b), no dialogs, permission prompts or downloads (3.4), history is not recorded (3.3a/3.5). Anything else that breaks is a backlog row.
3. **macOS notification prompt for the new identity.** The first RoomCore launch under `app.room.desktop` showed two "“Room” Notifications" banners (Chromium's alert service registering). Choose in System Settings ▸ Notifications ▸ Room (Room uses none of its own yet; "Off" is the conservative answer).
4. **A stray directory from a spike run.** A wrapper's `activate` relaunched Room.app on RoomCore without arguments once (B-47); it opened the real state at `~/Library/Application Support/Room` (a running-flag write, nothing else changed) and created `~/Library/Application Support/Room/RoomCore`. Delete that `RoomCore` directory if you do not want it; the next launch of the CEF app runs the full integrity check once (unclean flag) and goes on.
5. **The defaults domain moved** from `com.lekevicius.room` to `app.room.desktop`: Room's own settings live in its database, but anything stored in user defaults by hand (Sparkle's keys, `NSInitialToolTipDelay`, window frames) starts fresh. `defaults delete com.lekevicius.room` clears the old domain when you no longer need it.

## Phase 3.1b

1. **The keychain prompt left on screen.** The 3.1b keychain check launched the Developer ID–signed component build (`build/roomcore-signed/Room.app`) on a fresh state; macOS asked "Room wants to use your confidential information stored in “Room Safe Storage”" (the item was created on 2026-10-02 by the `com.lekevicius.room` identity, so the new `app.room.desktop` identity is not on its access list) and the page waited on the cookie store. The session killed Room and left the dialog alone: it is still on screen. Click **Deny** on that stale dialog (its requester is gone), or answer it in step 2.
2. **Answer the keychain prompt once on the signed build, then confirm no prompt.** `build/roomcore-signed/Room.app/Contents/MacOS/Room -RoomStateDirectory /tmp/room-3.1b/kc2 -RoomEngineDirectory /tmp/room-3.1b/kc2/engine -RoomStartURL https://example.com/` — enter the login password and choose **Always Allow**; example.com renders in the card. Quit (⌘Q), launch the same command again: no prompt, the page loads. (For the release build the follow-up prints the same command with its path; a Release-configuration app ignores `-RoomStateDirectory`/`-RoomEngineDirectory`, which are DEBUG-only, and would open the real state.)
3. **Sign the Sparkle update.** `scripts/sparkle-package.sh build/roomcore-signed/Room.app build/sparkle-3.1b` — `sign_update` reads the EdDSA private key from the login keychain (account `ed25519`) and macOS asks for permission (it waited behind the stale dialog of step 1 in the session). Choose **Always Allow** for `sign_update` and then for `generate_appcast`. The script prints the DMG size, the signature, the appcast entry (`build/sparkle-3.1b/appcast.xml`) and "verified". Paste the last lines into `research/notes/spike-results.md` "Phase 3.1b" ▸ Sparkle if you like; the follow-up repeats it on the release build.
4. **Licensed playback on a real service** (needs your account; the session played Shaka's public Widevine test stream, `research/spikes/phase-3.1b/widevine-demo.html`): `build/roomcore/DerivedData/Build/Products/Debug/Room.app/Contents/MacOS/Room -RoomStateDirectory /tmp/room-3.1b/drm -RoomEngineDirectory /tmp/room-3.1b/drm/engine -RoomStartURL https://www.netflix.com/` — sign in, play any title for a minute; note whether it plays, at what resolution (Netflix's ⌃⌥⇧D overlay), and any error code. Then the same with `https://open.spotify.com/` and one song. The first EME use downloads the Widevine CDM (the stated exception, ~5 s).
5. **The CEF app's real state got one launch** (B-47, while the fix was being tried): JXA's `Application(pid).activate()` relaunched Room.app on CEF without arguments at 18:09:27 when a spike quit mid-call; it opened `~/Library/Application Support/Room` and was quit 3 s later by the wrapper (the WAL changed; nothing else). Nothing to do unless that state matters to you; the wrappers now send AppleEvents to the pid with `scripts/lib/room-ae.swift` and never launch anything.

## Phase 3.1b-2

1. **The keychain check, now on the notarized release copy.** 3.1b's steps 2–3 named `build/roomcore-signed/Room.app` (the signed component build); it was deleted in 3.1b-2 to free the internal disk (3.7 GB free at one point). Use the notarized release copy instead, on a throwaway state (the Release app ignores `-RoomEngineDirectory`; `--user-data-dir` keeps the engine data out of your real data root):
   `build/roomcore-release-signed/Room.app/Contents/MacOS/Room -RoomStateDirectory /tmp/room-3.1b2/kc -RoomStartURL https://example.com/ --user-data-dir=/tmp/room-3.1b2/kc/engine`
   Expected: one "Room wants to use … “Room Safe Storage”" prompt; choose Always Allow; the page loads. ⌘Q and run the same command again: no prompt, the page loads within a second. Then the Sparkle signature: `scripts/sparkle-package.sh build/roomcore-release-signed/Room.app build/sparkle-3.1b2` and allow `sign_update` to read the `ed25519` key; the appcast's `sparkle:edSignature` and "verified" at the end are the result (the DMG is 184,497,802 bytes).
2. **The laptop's checkout after the series change.** 0001 and 0004 changed; `scripts/roomcore-apply.sh` now rebuilds the `room` branch from the first changed patch (only files whose content changes are rewritten) but refuses while the branch holds a commit outside the series. The laptop still carries `room: 0010-shutdown-worker-start-priority` (3.1a step 1): drop it first (`git -C "$CHROMIUM_ROOT/src" rebase --onto <0010-commit>^ <0010-commit> room`), then `scripts/roomcore-apply.sh` twice (the second run says "0 applied, 11 already") and rebuild `out/dev` (a `//base` file changes back, so a long relink).
3. **Disk space on the Mac mini.** The internal disk had 3.5–6 GB free during this session (430 of 460 GiB used); packaging the release build needs about 5 GB (framework stage, 2.2 GB of dSYMs, two apps) and filled the disk once. Free space where you choose (the session deleted only regenerable build caches under `build/`: three CI DerivedData copies, `DerivedDataOpt`, the 3.1b signed clone).

## Phase 3.2a

Room.app on RoomCore with a throwaway state: `build/roomcore/DerivedData/Build/Products/Debug/Room.app/Contents/MacOS/Room -RoomStateDirectory /tmp/room-3.2a/hand -RoomEngineDirectory /tmp/room-3.2a/hand/engine -RoomSidebarFixture demo` (open `research/spikes/phase-1.4/popups.html` from the address field as a `file://` URL).

1. **Links and popups by hand.** Click "target=_blank link", "window.open()" and "documentPictureInPicture.requestWindow()". Expected: each opens a Today tab right under Popups, selected, with no second window anywhere (Mission Control, ⌘\`); the PiP tab shows "Room document picture-in-picture" at card size (B-51). Then ⌘-click and middle-click a link on any real page: a background Today tab, no window; ⇧-click: a selected Today tab (Chrome's NEW_WINDOW), no window.
2. **The status pill.** Hover links on a real page (Wikipedia): the pill shows each URL and goes when the pointer leaves the link. The session could not hover by synthetic events in Room.app (B-52); the engine delivered the hovered link in the embryo drive.
3. **Element fullscreen.** On a YouTube video press the fullscreen button: the window goes fullscreen with the video edge to edge; Esc returns to the window with the sidebar. Then enter again and press the green button (or ⌃⌘F): the page leaves fullscreen too. There is no "Press Esc to exit" banner yet (B-49).
4. **Activation does not steal focus.** Open a page that calls `window.focus()` or opens a popup a few seconds after load (any site whose sign-in opens a window will do), then switch to another application before it fires: Room must not come to the front (RoomCore logs "Activate() while the application is inactive; not stealing focus"); the new tab is there when you return.

## Phase 3.2b

Room.app on RoomCore with a throwaway state: `build/roomcore/DerivedData/Build/Products/Debug/Room.app/Contents/MacOS/Room -RoomStateDirectory /tmp/room-3.2b/hand -RoomEngineDirectory /tmp/room-3.2b/hand/engine -RoomSidebarFixture demo`.

1. **⌘Q with a page that asks to stay.** Open `research/spikes/phase-2.6/dialogs.html` as a `file://` URL, click "Arm beforeunload", then press ⌘Q (the menu's key, not a script). Expected: Chrome's "Leave site?" dialog over the page (still Chrome's Views dialog until 3.4b routes it to Room's sheet); click **Cancel/Stay**: Room keeps running with every tab as it was. ⌘Q again and **Leave**: Room quits in well under a second. Repeat with the Dock icon's Quit (that path is AppKit's quit Apple event, which the session fixed: it waited forever before the fix).
2. **Links from other apps go to Room now.** With Room running, `open -a <the app above> https://example.com/` from Terminal and a link from another app's Open With: each becomes a selected Today tab (the spike did this by script; one by hand confirms nothing else intercepts). Then close the window with ⇧⌘W and click Room's Dock icon: the window comes back (Dock reopen is Room's `applicationShouldHandleReopen` now).
3. **Keys from a page on your own layout.** On any page with a text field, type a few words, then ⌘L and ⌘T: the palette opens (the page never sees them); ⌘C/⌘V/⌘Z work in the field; ⌘= / ⌘- zoom. Do it once with Colemak and once with ABC or Lithuanian selected in the menu bar's input menu: the spike sends events built from each layout's data but AppKit matches menu keys through the active input source, so only real typing proves the non-active layouts (the Phase 1.4 note; LithuanianColemak is not installed on the Mac mini).
4. **Crash recovery flags.** Start Room, wait a few seconds, `kill -9` it from Terminal, start it again: Room's log (`-RoomStateDirectory` run from Terminal shows it on stderr) says `Room: previous exit clean=false (store uncleanExit=true, engine lastExitWasClean Default=false)`; quit normally and start once more: `clean=true`.

## Phase 3.3a

Room.app on RoomCore with a throwaway state: `build/roomcore/DerivedData/Build/Products/Debug/Room.app/Contents/MacOS/Room -RoomStateDirectory /tmp/room-3.3a/hand -RoomEngineDirectory /tmp/room-3.3a/hand/engine -RoomSidebarFixture demo`.

1. **Peek by hand.** Pin a news site (drag a Today tab into the pinned section), click a link to another site in it: Peek opens over the page. Click a same-site link: it navigates in place. On a page that rewrites a link's `href` on mousedown (Google results do), the click still opens Peek on RoomCore (B-33: the engine knows it was a link; CEF guessed from the status text). ⇧-click a link on any page: Peek.
2. **A plain-HTTP site.** Type `neverssl.com` in the address field: Chrome's "ask before HTTP" dialog appears over the page (a Views dialog; Room crashed here before this session). Continue to the site: the header's site icon shows "not secure". On `https://example.com` it shows the padlock.
3. **Favicons and colours.** Visit a few sites: each sidebar row shows its favicon while loaded and after a relaunch (the app's cache). A site with a dark background (e.g. `https://github.com` in dark mode) fills the card with its colour during a window resize.
4. **Zoom per host.** Open two Wikipedia articles, zoom one with ⌘=, select the other: it is zoomed too (Chrome's per-host zoom, B-27), and the indicator shows the level when you zoom there.
5. **Audio.** Play a YouTube video: the row's speaker appears; pause it: the speaker goes about two seconds later; ⇧⌘M mutes it.
6. **Discard keeps history.** Navigate a Today tab two links deep, Debug ▸ Discard Background Pages (with another tab selected), then select it again: it reloads, and Back goes to the page before.
7. **Closing a page that asks to stay.** On `research/spikes/phase-2.6/dialogs.html` (as a `file://` URL) click "Arm beforeunload", then ⌘W: Chrome's "Leave site?" dialog (Views until 3.4b). Note: "Stay" keeps the page alive in the engine but the sidebar entry is already gone (the host learns the answer only through 3.4b's dialog delegate); "Leave" closes it.

## Phase 3.3b

Room.app on RoomCore with a throwaway state: `build/roomcore/DerivedData/Build/Products/Debug/Room.app/Contents/MacOS/Room -RoomStateDirectory /tmp/room-3.3b/hand -RoomEngineDirectory /tmp/room-3.3b/hand/engine -RoomSidebarFixture demo`.

0. **Stale system dialogs.** Four "Room quit unexpectedly" dialogs are on the Mac mini's screen (05:24 ×2 from 3.3a's runs; 06:59 ×2 from this session launching today's app over the 3.1b-2 release framework, which lacks 3.2b's API). Sessions do not answer system dialogs: please click Ignore on each.
1. **Find while typing.** On a long page, ⌘F and type a word slowly: the first three letters highlight their first match after about 0.4 s (Chromium's short-query delay, Chrome behaves the same), from the fourth letter on it follows each key at once; ⌘G / ⇧⌘G step, Esc puts the keyboard back in the page.
2. **Print preview.** ⌘P on a page: Chrome's print preview appears over the card (Views, B-29). Change the destination to "Save as PDF", save, check the PDF; Cancel and Esc close it; the window stays usable behind it. On a site that changes its URL by script (developer.apple.com), Chrome closes the preview by itself: expected.
3. **DevTools pane.** ⌥⌘I opens DevTools in the pane under the page (not a window): drag the divider, pick Elements, Console, type `1+1` in the console (keys reach the front-end), ⌥⌘I again closes it with the keyboard back in the page. ⌥⌘C turns on the picker: click an element on the page and Elements selects it. Right-click ▸ Inspect is Chrome's menu until 3.4a.
4. **A Views dialog over the window.** With the modal anchor now above Room's window: open `research/spikes/phase-2.6/permissions.html` or any page that shows a Chrome bubble (autofill on a sign-in form); check the bubble shows over the card and that clicks on the page itself are not swallowed by an invisible layer (the anchor is transparent and ignores the mouse).
5. **Release build, no port.** On the next release build (3.8): `lsof -nP -iTCP -sTCP:LISTEN -a -p $(pgrep -n -f Room.app/Contents/MacOS/Room)` lists no debugging port.

## Phase 3.4a

Room.app on RoomCore with a throwaway state: `build/roomcore/DerivedData/Build/Products/Debug/Room.app/Contents/MacOS/Room -RoomStateDirectory /tmp/room-3.4a/hand -RoomEngineDirectory /tmp/room-3.4a/hand/engine -RoomSidebarFixture demo`. The 2.6 pages: `python3 research/spikes/phase-2.6/server.py` (http://127.0.0.1:8766, https://127.0.0.1:8767).

0. **Stale system dialogs.** One more "Room quit unexpectedly" (09:14, this session's crash in the site panel's Clear before the fix) beside the earlier ones; please click Ignore on each.
1. **Location (B-26).** On `http://127.0.0.1:8766/permissions.html` click Location and Allow in Room's popover. If macOS asks whether Room may use your location, allow it (or System Settings › Privacy & Security › Location Services › Room on). Reload: the page's `navigator.permissions.query({name:'geolocation'})` (in the console of DevTools) reads `granted` and the position arrives. Before macOS authorizes Room it reads `prompt` (Chrome's own system gating; the site panel already shows Allow).
2. **Camera and microphone.** With a camera (any Mac with one): Camera and microphone on the same page: Room's popover lists both with Allow This Time; Allow This Time → the page reads `granted`, a reload asks again. Turn Room off in System Settings › Privacy & Security › Camera and ask again: the popover adds "macOS doesn't allow Room to do this…".
3. **Context menus.** Right-click a link, an image, selected text and a misspelled word in a text field: Room's items first, then Chrome's (suggestions, Add to Dictionary, Look Up "…", Copy Link Address, Save Image As…). Choose a suggestion: the word is replaced; Look Up opens the dictionary panel; Copy Link Address puts the link on the pasteboard (no Chrome toast); Esc closes the menu. Right-click twice quickly: one menu.
4. **Downloads.** `downloads.html`: start the slow one, pause and resume it from the popover; quit Room while it runs (no Chrome prompt; the download is cancelled), start Room again: the popover lists it as cancelled with the earlier ones. Clear empties the popover, but the next launch lists them again (B-59).
5. **Sign-in and certificates.** `http://127.0.0.1:8766/auth` (room / secret): Room's sheet, never Chrome's dialog. `https://127.0.0.1:8767/secure.html`: Room's interstitial, Show Details, Visit … Anyway. `https://subdomain.preloaded-hsts.badssl.com/`: Room's interstitial without Visit … Anyway. Then the site panel on 127.0.0.1:8767 › Reset Permissions and reload: the interstitial is back (B-43).
6. **Files.** `files.html`: each button opens Room's open panel as a sheet; choose a real image, two PDFs, and a folder: the page lists them (the folder's files with their relative paths).
